# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

HBX fork of BigCommerce's **Cornerstone** Stencil theme (branch `hbx-conversion`, upstream `master`). It is mid-migration: the legacy theme (Handlebars `.html` in `templates/`, JS in `assets/js/`, SCSS in `assets/scss/`, webpack build) still works, and a new Vite + TypeScript + React-JSX toolchain was added alongside it. Node 24 / npm 11 (see `.nvmrc`, README) — `package-lock.json` must only change for the package being updated.

## Commands

```bash
npm run vite-dev          # Vite dev server (:5173); allowed host *.trycloudflare.com
npm run cloudflared-tunnel # expose :5173 via cloudflared
npm run vite-build        # tsc -b && vite build  -> ./dist
npm run prepare-sass-runtime  # rebuild @bigcommerce/node-sass (run if sass fails)

npm run webpack-build     # legacy prod build -> assets/dist (webpack.prod.js)
npm run webpack-buildDev  # legacy dev build

npm test                  # jest (jsdom, jasmine2)
npx jest assets/js/test-unit/theme/cart.spec.js   # single test file
npx jest -t "name"        # single test by name
npx grunt check           # eslint + jest + stylelint (grunt/aliases.yml)
npx grunt eslint          # JS lint only (airbnb, .eslintrc)
npm run stylelint         # SCSS lint (stylelint:fix to autofix)
npx grunt svgstore        # rebuild icon sprite from assets/icons (also default `grunt`)
```

CI (`.github/workflows/pull_request_review.yml`) only does a Stencil theme bundling test on Node 24.

## Architecture

**Two parallel build pipelines produce the same output names** (`theme-bundle.*.js`) so templates don't care which one built them:
- `webpack.common.js` — entries `main`, `head_async`, `font`, `polyfills`, `polyfill_form_data` -> `assets/dist/`.
- `vite.config.ts` — `jsEntry` mirrors those webpack entries, and `resolve.alias` / `renderBuiltUrl` mirror webpack's aliases and `__webpack_public_path__` (set from `{{cdn 'assets/dist/'}}` in `templates/layout/base.html`). **When changing entries or aliases in one config, update the other.** Vite also injects `$`/`jQuery`/`window.jQuery` globals for legacy code. Note `jsEntry` paths like `./app.js` are resolved by the Stencil plugin (legacy `assets/js/`), not `src/`.

**Vite plugins** (from `@mainlanddev/*`):
- `BigcommerceStencil` — runs/builds the Stencil theme (`templates: ./templates`, flat bundle mode, `buildToPath: ./dist`, `variantIndex: 3`, channel 1). `dist/` and `config.stencil.json`/`secrets.stencil.json` are gitignored — never commit secrets.
- `BigcommerceReact` — compiles JSX in `src/templates/{components,layout,pages}` into Handlebars v4 templates (`jsxImportSource: @mainlanddev/bigcommerce-react`). Every `templates/**/*.html` has a TSX twin there (see "TSX templates" below). `src/main.ts` is scaffolding. Alias `@` -> `src`.

**Legacy JS runtime** (`assets/js/`): `app.js` maps the page-type string from the template context (e.g. `account_orderstatus`, `product`, `cart`) to a lazy `import('./theme/<page>')`; each page module extends `PageManager` (`theme/page-manager.js`). `theme/global.js` runs on every page. Template data reaches JS through the `{{inject}}` / `{{jsContext}}` helpers (`this.context`). Polyfills load conditionally via feature detection in `templates/components/common/polyfill-script.html`.

**Theme metadata**: `config.json` (settings/variations, `handlebars_v4`), `schema*.json`, `lang/` (translations), `meta/`, `schema.graphql` (storefront GraphQL, `.graphqlrc`).

**Tests** live in `assets/js/test-unit/` (mirrors `assets/js/theme/`), `*.spec.js`; jest config maps `jstree`, `lazysizes`, `slick-carousel`, `svg-injector` to dist files. TS/JSX under `src/` is not covered by jest (babel-jest on `.js` only).

## TSX templates (HBX port)

Every `templates/**/*.html` has a TSX twin at the same path under `src/templates/` (kebab-case, e.g. `components/cart/content.html` ->
`src/templates/components/cart/content.tsx`). The plugin compiles them to Handlebars v4 in `dist/templates/<path>.html`; **a TSX replaces the
`.html` of the same path**, so the originals are kept only as the source of truth until parity is signed off. Do not edit both: change the TSX.
`DEVIATIONS.md` (repo root) is the master list of every place the TSX output differs from the original and why; add to it when you add a deviation.

### Verify
- `npm run vite-build` must exit 0 (it runs `tsc -b` first).
- `src/theme-types.d.ts` is generated by `vite build` (after `tsc`) from `config.json`, `schema.json`, `lang/en.json`. Do not hand-edit; if those
  files change, run `npx vite build` once to regenerate. It must exist before `tsc -b` on a clean checkout.
- `vite-build` needs `config.stencil.json` (not `secrets.stencil.json`). Never print or commit either.
- Compiled output lands in `dist/templates/<path>.html` (one line, no whitespace); compare it with the original when porting.

### Conventions
- File shapes: partials `export default $asPartial<Props>(...)`; layouts `$layout`; pages `$page<ThemePageX>({frontmatter, content})` plus an explicit
  `<$StencilPartial name={$string('page')}>` and `<$Partial name="layout/base"/>` (`$page` does not add layout wiring); option/form components that
  `dynamicComponent` resolves use `$dynamic('<type>', ...)`.
- HBX makes every partial argument explicit and named (avoids namespace collisions). Props keep the **exact name of the ambient key** they replace
  (`cart`, `theme_settings`, `customer`, `settings`, ...). ~27 partials are also requested by JS at runtime with no page context (see
  `assets/js`: `template:` / `render_with`; list in `DEVIATIONS.md`); the response root must supply those names. The build cannot test them.
- Page context comes from the typed `$page<ThemePageX>` `ctx`, handed down as props. No `any`, `@ts-ignore`, or loose string paths. Missing library
  context keys: add an extension type in `src/context*.ts` (assignable to the lib type, e.g. `Omit<> &`), never a cast, and log it.
- Keep markup 1-1: same classes, ids, `data-*`, ARIA, `lang`/`inject` keys, branches. No cleanup or accessibility fixes in a port; do those separately.
- React renders some things differently from the originals: `className`/`htmlFor`/`tabIndex`; a bare `data-x` must be `data-x=""`; `style` as an
  object; entities in text via `{$$raw('&times;')}`; inline `<script>` bodies as `{[$$raw('js'), token, $$raw('js')]}`; `<textarea>` uses
  `defaultValue`; non-standard `<icon>` uses the `Icon` stub (`src/components/icon.ts`, purpose unidentified: do not remove).
- Escape hatch `$parseHandlebarsDangerously(...)` (raw Handlebars) is allowed only where the library cannot express the construct (conditional tag
  names or open/close tag pairs, `{{#for}}` with `$index`, array `this`, `getImage` on unsized images, front-matter keys the types reject,
  `<title>`/`<meta>` hoisting by React 19). Keep fragments as small as possible, copy the original text verbatim, and list the file and reason in
  `DEVIATIONS.md` section 8.2. Raw fragments are not checked by `tsc`.
- Each TSX quotes its original source: a header (`Source: templates/<path>.html`, plus the front matter) and an `html L<n>: ...` comment before every element, helper component and child expression (`{/* */}` in JSX child position, `/* */` in expression position). Keep them current when you edit a node; they never affect compiled output. Original `{{!-- --}}` comments that were dropped by the port survive only in these comments.
- Write TSX with the Write/Edit tools; shell heredocs and `node -e` break on `$`, backticks and quotes.

### Known library limits (unverified at runtime; keep working around, log, do not fight)
- `{{#with}}` compiles to `as |ctx|`; every block/partial gets `root=@root` (deliberate lib workaround for `@root` not propagating).
- Tokens inside a top-level `$$` attribute array get spaces around them (`alt=" {{x}} "`).
- Lib types are incomplete or wrong in places (cart line items, `shipping_messages`, `forms`/`pagination` unions, `coupons`, `downloads: never`). Check
  the real template data before trusting a type.

## Gotchas

- `tsconfig.app.json` is strict about `noUnusedLocals`/`noUnusedParameters`, `verbatimModuleSyntax`, `erasableSyntaxOnly` (no enums/namespaces/param properties).
- `"type": "module"` in package.json: root config files using `require` need `.cjs` (see `stencil.conf.cjs`); `jest.config.js` and `webpack.*.js` still use CommonJS, so check they load before touching them.
- Upstream Cornerstone conventions apply: Conventional Commits with ticket ids (e.g. `feat(storefront): TRAC-1023 ...`).
- **Every commit updates `CHANGELOG.md`.** Entries go under `## Draft` (the pending batch for the next release); the heading is renamed to the version and date only when a release is cut, so a normal commit never creates a version section. Link the PR as `[#XXXX](...)` until its number exists.
