# DEVIATIONS: `templates/**/*.html` -> `src/templates/**/*.tsx`

Master record of every difference between a ported TSX template and its original `.html`.
Whitespace-only and serializer-equivalent HTML differences are not deviations (see "Not deviations").
Entry format: **file(s)** | original construct | what the TSX does instead | reason | impact (none / markup / behaviour) | library-fixable?

Status: 210 of 210 templates ported; `vite-build` green; `--known` diff: 192 identical, 18 differ (section 8.3 and the per-batch tables in section 7), 0 missing. 23 files use the raw-Handlebars escape hatch (section 8.2). Diff tool: 32/32 tests.

## 1. Global (apply to many or all files)

- **Named arguments instead of ambient context** | any partial the original calls with no args (or fewer args) and which reads page context ambiently | the TSX component declares named props for the data it reads and the page passes them, so the compiled call gains hash args, e.g. `{{> components/cart/page-title cart=cart}}` | by design of HBX: every partial argument is explicit and named, to prevent namespace collisions; page context comes from `$theme<...>()` at page level and is handed down | impact: none (hash args extend the partial's context; every ambient lookup still resolves) | not library-related. **Naming rule:** a prop keeps the exact name of the ambient key it replaces (`cart`, `theme_settings`, `customer`, `settings`), so the partial also works when JS renders it (next entry).
- **Partials rendered at runtime by JS, with no page context** | the ~27 templates JS requests via `template:` / `render_with` (list in section 5) | no change to the TSX, but they are only reached at runtime, so a green build and a clean diff do NOT prove them | the JS asks Stencil for a template by name and the response is its root context (e.g. cart API data) rather than a page's context | impact: risk only; props named after ambient keys (rule above) resolve against that root | n/a. These need runtime testing later.
- **`root=@root` on `{{#block}}` / `{{#partial}}`** | all pages and layouts | lib appends `root=@root` to every block/partial tag | deliberate lib workaround: `@root` is not passed through to block children correctly (per user) | impact: none expected | not fixable in theme.
- **ThemeContext keys missing from the library** | `locale_name`, `head.config`, `template` | `ExtendedThemeContext` in `src/context.ts`; pages/layouts call `$theme<ExtendedThemeContext>()` | lib `ThemeContext` does not declare them | none | library-fixable.
- **Theme types generated by the plugin** | n/a | `vite.config.ts` `themeTypes` writes `src/theme-types.d.ts` from `config.json` / `schema.json` / `lang/en.json` | lib expects `BigcommerceJSX.ThemeSettings`, `LangStrings` to be declared | none (toolchain) | n/a. The file is written during `vite build`, after `tsc -b`, so keep it in the tree; regenerate with `npx vite build` when config.json, schema.json or lang/en.json change.
- **New devDependencies** | `react`, `react-dom` (19.3.1), `@types/react` | required by the lib for JSX types | approved by user | none | n/a.
